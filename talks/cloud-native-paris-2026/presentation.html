SECURED MODE / UPSTREAM CHANGES IN REVIEW
7:30–10:00. One identity provider (Keycloak) for everyone. The Registry already supports OIDC and roles in a release; the client side (the Quarkus LangChain4j extensions sending credentials to the Registry and to A2A agents) is in review or proposed upstream, and this demo builds it from a pinned branch. Show: curl -sS -o /dev/null -w 'HTTP %{http_code}\n' -X POST http://localhost:11010/ -H 'Content-Type: application/json' -d '{}' returns 401; in the console, alice can edit, bob in a private window can only read. The Agent Cards are protected too: the client sends its token when it fetches them (the A2A spec also allows public cards). Then go on with the briefing: every call behind it now carries a token.

    06 / The design rule
    
        
    Put each guarantee
    in the right place.
    
        
    
          
    01Locate registered endpointsRegistry extensions
    
          
    02Choose roles, order and argument encodingApplication code
    
          
    03Check a candidate card or toolRegistry publication rules
    
          
    04Verify deployed behaviorTests + deployment process
    
        
    
        
    Observed metadata is not deployment pinning. Lifecycle and authorization need their own policy.
    Observed metadata is not deployment pinning. Roles decide who may publish; lifecycle needs its own policy.
    
        
    CONTRACT COMPATIBILITY ≠ RUNTIME CORRECTNESS11 / 13
    
        
    21:30–23:15. This is the single boundary summary. The example is loopback-only and unauthenticated, has no deprecation gate, and does not pin remote deployments. Registered metadata reads are not a transactional snapshot across services. Separate publication proof from behavioral testing.
    
        
    20:30–23:00. This is the single boundary summary. Every hop is authenticated, but on loopback with demo secrets: no tenant boundaries, key rotation or production credential management. No deprecation gate, and remote deployments are not pinned. Registered metadata reads are not a transactional snapshot across services. Separate publication proof from behavioral testing.
