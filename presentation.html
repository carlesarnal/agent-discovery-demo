05 / An integration lesson

Let the model choose the city.
Let code shape the call.

Generic tool calls

More room for shape errors.

In sample testing, the model sometimes sent an object instead of a JSON string—or omitted the connection key.

Typed application boundary

One input. Explicit sequencing.

weatherForCity(String city)
  search → connect → invoke
  Jackson encodes the JSON

The application owns argument encoding.

The weather assistant uses this as a tool; the fixed briefing calls it directly.

REDUCE ACCIDENTAL COMPLEXITY AT THE BOUNDARY10 / 13
This observation is documented in the pinned sample's verification record. It is not a quantified benchmark. The separate /workflow/weather endpoint demonstrates model-driven tool use; the briefing does not rely on the model to plan the sequence. A typed wrapper reduces shape errors, not every bad input or authorization risk.
06 / The design rule

Put each guarantee
in the right place.

01Locate registered endpointsRegistry extensions
02Choose roles, order and argument encodingApplication code
03Check a candidate cardRegistry publication rules
04Verify deployed behaviorTests + deployment process

Observed metadata is not deployment pinning. Lifecycle and authorization need their own policy.

CONTRACT COMPATIBILITY ≠ RUNTIME CORRECTNESS11 / 13
19–22 minutes. This is the single boundary summary. The example is loopback-only and unauthenticated, has no deprecation gate, and does not pin remote deployments. Registered metadata reads are not a transactional snapshot across services. Separate publication proof from behavioral testing.
